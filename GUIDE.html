How to change this website

You built a real website. This guide teaches you how it works and how to change it yourself — assuming you know a little Python and nothing else.

You already know more than you think. You've started Python. Loops, variables, functions, indentation — that all transfers. This guide points out the Python parallel every time something new appears.

How to use this

  • Go in order the first time. Sections 1–5 get you making real changes.
  • Actually try the interactive bits. Sliders, quizzes and playgrounds are here because reading about layout teaches you far less than dragging a slider does.
  • You cannot break anything permanently. Your work is saved in Git. Section 10 shows you how to undo any mistake with one command.

Keep this file. It's saved in your project folder as GUIDE.html. Double-click it any time to open it in your browser. It works offline, forever, with no internet needed.

1 · Get it running on your computer

Before changing anything, make sure you can see the site running. Open a terminal (on Windows: search for PowerShell) and navigate to the project folder.

Terminal — do this once
cd "D:\Projects\marketing 1"
npm install

npm install downloads the libraries the project depends on. It's the same idea as pip install in Python. It takes a few minutes the first time and creates a node_modules folder — never edit that folder.

Terminal — every time you work
npm run web

This starts a development server and prints a web address, usually http://localhost:8081. Open it in your browser. Leave this terminal running while you work — when you save a file, the page updates by itself.

What is "localhost" and why 8081?

localhost means "this computer". The site isn't on the internet — it's being served by the program you just started, and only you can see it. The number (8081) is the port, like a door number, so your computer knows which program to hand the request to. Nobody else can reach it.

The other commands, and when you need them
CommandWhat it does
npm run webDevelopment server. Use this while working.
npm run typecheckChecks for mistakes without running. Run before you finish.
npm run build:webBuilds the finished site into dist/ for publishing.
node serve-dist.jsPreviews the finished build at port 4174.

To stop a running server, click the terminal and press Ctrl + C.

2 · The big idea (don't skip this)

Most websites are written in HTML. This one is not. It's written in React Native — a system designed for phone apps that can also produce a website.

That means normal HTML tutorials will give you code that does not work here. Here's the translation:

Try it · Flip between what you'd write elsewhere and what you write here
React Native — correct
import { View, Text } from 'react-native';

<View style={{ padding: 20, backgroundColor: '#eee' }}>
  <Text style={{ fontSize: 16 }}>Hello</Text>
</View>

Note the differences: View instead of div, Text instead of p, and 20 as a plain number rather than the string '20px'.

The five rules that follow from this

RuleWhy it matters
All text goes inside <Text> A bare word inside a <View> crashes the page. This is the #1 beginner error.
Sizes are numbers, not strings padding: 20 ✅   padding: '20px' ❌
Nothing is inherited Setting a font on a parent does not affect children. Set it on each <Text>.
Stacking is vertical by default In HTML boxes stack vertically too, but here you must write flexDirection:'row' to go sideways.
No CSS files, no hover in CSS Styles live in the component. Hover uses onHoverIn/onHoverOut.
Quick check — which of these will crash the page?

Here is a real, complete component. Every line is explained underneath.

A component, annotated
import { View, Text } from 'react-native';          // 1
import { color, font } from '@/theme/tokens';       // 2

export function Greeting({ name }) {                // 3
  return (                                          // 4
    <View style={{ padding: 20 }}>                   // 5
      <Text style={{ color: color.ink,
                     fontFamily: font.body }}>      // 6
        Hello, {name}                               // 7
      </Text>
    </View>
  );
}
  1. Import the building blocks. Like from x import y in Python.
  2. Import the design tokens. @/ is a shortcut meaning the src folder. So this reads src/theme/tokens.
  3. Define the component. export makes it usable by other files. { name } receives an input — called a prop.
  4. Return what to display. Same as Python's return.
  5. A container. The outer { } means "JavaScript here", the inner { } is the style object. That's why you see {{ }} so often.
  6. Styling from tokens rather than typed-in colours (section 6 explains why).
  7. Insert a variable into text with { } — like a Python f-string.
Why the double braces {{ }}?

They're two different things stacked. The outer { } tells the template "switch to JavaScript now". The inner { } is an ordinary object, exactly like a Python dictionary. So style={{ padding: 20 }} means: the style property equals the object {padding: 20}.

5 · Your first real change

Let's change some words on the site. This is the safest possible edit — do it now while npm run web is running so you see it happen live.

1Open the file

Open src/data/contentPages.ts in your editor (VS Code is free and excellent). Press Ctrl+F and search for a phrase you can see on the website — say No open roles or What does Vendly cost.

2Change the text between the quotes

Before
{ q: 'What does Vendly cost?', a: 'The Starter plan is free and stays free…' },
After — only the words inside the quotes changed
{ q: 'How much does it cost?', a: 'Starter is free forever…' },

The three characters that break everything. Keep the quotes ', the commas , and the braces { } exactly where they are. Only change letters between quotes. If your text contains an apostrophe — like don't — write it as "don't" with double quotes around the whole thing, or the apostrophe will end the text early.

3Save and look

Press Ctrl+S. Your browser updates within a second or two. If it doesn't, refresh the page. If you see a red error screen, jump to section 10 — it's almost always a missing quote or comma.

6 · Colours and fonts

Every colour on the site is defined once, in src/theme/tokens.ts. Components refer to them by name. Change the name's value and it updates everywhere at once.

Explore · click a colour to see its name and where it's used
Using a token — always do this
import { color, font } from '@/theme/tokens';

<Text style={{ color: color.ink, fontFamily: font.body }}>Hi</Text>

Don't type raw colours like '#2b4cf2' into a component. If the brand colour ever changes you'd have to hunt through 50 files. Using color.accent means one edit changes everything — and the site stays visually consistent.

The font names

TokenUse it for
font.displayBoldBig headings
font.bodyNormal paragraphs
font.bodySemiSlightly bolder body text, buttons
font.monoSmall uppercase labels
Why is text sizing written as metrics(15, 1.6)?

In CSS you can say line-height is 1.6 and the browser multiplies it by the font size. React Native needs an exact pixel number instead. metrics() does that multiplication for you: metrics(15, 1.6) means "15px text with 24px line height". Always use it rather than setting fontSize alone — it keeps spacing consistent across the site.

Making it work on phones

Screens vary. This project reads the width with a helper called useViewport():

Responsive layout
const { isMobile, gutter, f } = useViewport();

<View style={{
  flexDirection: isMobile ? 'column' : 'row',   // stack on phones
  padding: gutter,                              // edge spacing
  fontSize: f(20, 4, 40),                       // min 20, grows, max 40
}}>

condition ? a : b is shorthand for if/else — it reads "if isMobile then column, otherwise row". Python's version is a if condition else b.

8 · Adding a whole new page

This project uses file-based routing: creating a file creates a web address. No configuration, no list to register it in.

Create app/hello.tsx and it becomes yoursite.com/hello. Paste this in:

app/hello.tsx — a complete working page
import React from 'react';
import { Text, View } from 'react-native';
import { ContentPage } from '@/components/ContentPage';
import { Reveal } from '@/components/Reveal';
import { metrics } from '@/components/Type';
import { color, font } from '@/theme/tokens';

export default function HelloPage() {
  return (
    <ContentPage
      eyebrow="Company"
      title="Hello"
      lede="A short line underneath the heading."
    >
      <Reveal index={0}>
        <View style={{ maxWidth: 640 }}>
          <Text style={[{ fontFamily: font.body, color: color.textMuted },
                        metrics(15, 1.6)]}>
            Your paragraph goes here.
          </Text>
        </View>
      </Reveal>
    </ContentPage>
  );
}

Save, then visit http://localhost:8081/hello. You get the navigation bar, footer, scroll animations and search-engine tags for free, because ContentPage supplies all of it.

PieceWhat it gives you
ContentPageNav, footer, dark heading area, SEO tags
eyebrowSmall label above the title
titleThe big heading, and the browser tab name
ledeSupporting line, also used as the search description
RevealFades in on scroll. index staggers the order.

To link to it from the footer, add an entry to ROUTES in src/sections/SiteFooter.tsx.

One catch, for pages with square brackets. A file like [slug].tsx serves many addresses from one file. Those need a list of every address at the bottom of the file (generateStaticParams). If you add a new legal page, add its name to that list too — otherwise it won't be built.

9 · The honesty rules — please keep these

This is the most important section, and it's not about code.

Vendly hasn't launched. There are no apps in the stores, no accounts, no support inbox. An earlier version of this site claimed all of those things. Every claim was removed, because people act on what a website tells them — they'd have applied for jobs that didn't exist and waited for replies from an inbox nobody reads.

Never add a claim you can't back up. No invented statistics, no fake job listings, no "message sent" for a form that sends nothing, no download link that 404s, and no promises about encryption or data handling.

The two files that keep you honest

Instead of writing unverified facts into page text, they live in config files with a true/false switch. While the switch is false, the website automatically hides or softens that claim.

src/config/company.ts
// false = not confirmed yet → the site quietly hides it
supportEmail: fact('support@vendly.lk'),

// Once the mailbox genuinely exists and someone reads it:
supportEmail: fact('support@vendly.lk', true),
src/releases.ts
// Shows "Soon" instead of a broken download button
windows: { available: false, url: '.../Vendly-Setup.exe' },

// Only after the file really downloads:
windows: { available: true, url: '.../Vendly-Setup.exe' },

The rule of thumb. Before flipping any switch to true, open the link or send a test email yourself. If it works, flip it. If not, leave it — the site is already saying the honest thing.

10 · When it breaks (it will, that's normal)

Every programmer breaks things constantly. The skill isn't avoiding errors — it's reading them calmly. Error messages usually name the file and line number.

Red screen: "Unexpected token" or "Unexpected end of input"

A punctuation mistake — a missing quote, comma, or closing brace. Look at the line number in the message, then the line just above it. Most often it's an apostrophe inside single quotes: 'don't' breaks; use "don't".

"Text strings must be rendered within a <Text> component"

You put words directly inside a <View>. Wrap them: <View><Text>Hello</Text></View>.

"Cannot find module '@/something'"

The import path is wrong. @/ means the src folder, so @/theme/tokens is src/theme/tokens.ts. Check spelling and capitals — Tokens and tokens are different.

The page is blank / nothing appears until I scroll

Content animates in on scroll. If a page stays blank, its scroll container isn't reporting its height. Compare against a working page like app/company/[slug].tsx.

My content is cut off and the page won't scroll

A known trap. Tall content needs to be inside a <ScrollView> or it is simply clipped — the page won't scroll to reveal it. See app/get-app.tsx for the fix in context.

The undo button for everything

Your project uses Git, which remembers every saved version. If you're lost:

Throw away changes to one file
git checkout -- src/data/contentPages.ts
See what you've changed, before undoing anything
git status
git diff

Careful: git checkout -- permanently discards your unsaved edits to that file. Run git diff first to see what you'd be throwing away.

13 · Where to go next

You don't need to learn everything. In rough order of usefulness for this project:

  1. JavaScript basics — variables, functions, arrays, objects. You'll recognise most of it from Python. javascript.info
  2. React basics — components, props, state. react.dev/learn
  3. Flexbox — you've already used it above. reactnative.dev/docs/flexbox
  4. Expo — only when you need it, and read the version 57 docs specifically. Older tutorials will not match this project.

Using an AI tool instead? Give it the file INSTRUCTIONS.md in this project folder. It contains everything an AI assistant needs — the architecture, the conventions, the traps, and the honesty rules — written for exactly that purpose.

Honest advice

The fastest way to learn this codebase is to change something small and see what happens. Change a colour. Change a heading. Break something on purpose and read the error. You have Git, so nothing you do is permanent. That loop — change, look, understand — is how every developer actually learns.

Good luck with the project.
